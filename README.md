# World Studio — تطبيق سطح مكتب واحد: المباني + التضاريس

تطبيق واحد بتبويبين: **المباني** (BIM Builder – Game Edition) و**التضاريس** (TerrainForge). كل وحدة تعمل كعملية مستقلة وتُعرض في نافذة واحدة.

## كيف يعمل (مختصر)
```
WorldStudio.exe (مشغّل صغير)  ──►  يتأكد من البيئتين (مرة واحدة فقط)  ──►  studio.run
                                                                         ├─ المشرف: يشغّل الوحدات ويعيد تشغيلها إن تعطلت
                                                                         ├─ الصدفة (Shell): التبويبات + الإعدادات + التحديث
                                                                         └─ نافذة أصلية (pywebview / WebView2)
```
- **بيئتان دائمتان** في مجلد بياناتك (ويندوز: `%LOCALAPPDATA%\WorldStudio\env`): `app` (FastAPI + numpy + scipy + opencv + debim) و`bpy` (Python 3.11 + مكتبة bpy). تُبنى **مرة واحدة**؛ بعدها الإقلاع فوري. تُعاد فقط إن تغيّر ملف المتطلبات (وpip يثبّت الفرق فقط).
- **استخدام بيئتك الحالية:** لا تريد بيئة جديدة؟ أضف في `settings.json` (في مجلد البيانات) أو متغير بيئة:
  ```json
  { "envs": { "bpy": { "python": "C:\\path\\to\\your\\python.exe" } } }
  ```
  أو `STUDIO_PYTHON_BPY` / `STUDIO_PYTHON_APP`. البيئة الخاصة بك لا تُلمس أبداً، **ولا يُنزَّل ولا يُنشأ شيء لها**.
  - الأسهل: ⚙ الإعدادات داخل التطبيق ← «بيئات Python الخاصة بي» ← الصق مسار `python.exe` ← «حفظ وفحص» ← إعادة تشغيل.
  - أو من سطر الأوامر: `python -m studio.setup --app C:\envs\main\Scripts\python.exe --bpy C:\envs\bpy\Scripts\python.exe`
    (أو `--same` إن كانت بيئة واحدة فيها كل شيء). `python -m studio.setup --show` يعرض الحالة.
  - يُفحَص وجود الحزم المطلوبة (`fastapi, uvicorn, numpy, scipy, cv2, shapely, debim, …` و`bpy`) **دون تثبيت شيء**؛ إن نقص شيء تظهر رسالة بالنقص بدل أن يفشل التشغيل لاحقاً. التثبيت في بيئتك يتم فقط بأمرك: `pip install -r requirements/app.txt`.
- **البيانات** (مشاريع المباني، السجلات) في `%LOCALAPPDATA%\WorldStudio\data` ولا تُحذف عند التحديث أو إلغاء التثبيت.

## الإعداد بنقرة واحدة على ويندوز (`installing.bat`)
افتح **Anaconda Prompt** في مجلد المشروع ثم: `installing.bat` (أو `installing.bat golds world_build`).
1. ينسخ بيئة `golds` إلى `world_build` (الأصل لا يُمسّ)، 2. يثبّت **الناقص فقط** دون ترقية أو تخفيض ما هو موجود ويتأكد أن `import bpy` ينجح، ثم يسجّل البيئة في إعدادات World Studio،
3. يبني واجهتي الويب (Node.js)، 4. ينتج `dist\WorldStudio.exe` + اختصاراً على سطح المكتب (لهذا الجهاز؛ يقرأ مساري البيئة والمجلد من `WorldStudio.json` بجانبه)،
5. اختيارياً (إن وُجد Inno Setup): `dist\WorldStudio-Setup-<ver>.exe` لإرساله لشخص آخر؛ يبني المستلم بيئاته بنفسه عند أول تشغيل (يحتاج إنترنت). السجل في `installing.log`.

## من المنشأة إلى المباني إلى التصدير المشترك
1. في **التضاريس** أضف **منشأة** (قرية/مدينة/قلعة/برج…) بأداة «منشأة» وحدّد شكلها وحجمها وتُسوّى الأرض تحتها كالمعتاد.
2. **انقر نقراً مزدوجاً على المنشأة في الخريطة** (أو زر «ارسم المباني في BIM Builder» في لوحتها): يفتح تبويب **المباني** في نفس النافذة على مشروع خاص بهذه المنشأة. يُنشأ المشروع عند أول مرة ويُعاد استخدامه بعد ذلك، ويظهر **حدّ المنشأة** (دائرة أو مستطيل مدوَّر) منقّطاً في المحرر؛ مركز المنشأة = نقطة الأصل (0,0) بالأمتار. ارسم القرية/القلعة داخله.
3. زر **«← رجوع إلى التضاريس»** يحفظ ويعيدك؛ المنشأة تبقى مرتبطة بمشروعها (`bim_project` داخل ملف مشروع التضاريس).
4. من تبويب **التصدير** في التضاريس: **«تصدير العالم + المنشآت»** ينتج مجلداً واحداً:
```
<exports>/<اسم>_<تاريخ>/
  terrain/                 مربعات/صورة الارتفاع + build.json + import_build.py + الأقنعة …
  sites/<id>/<اسم>.glb     مجسّم كل منشأة رسمتها
  sites.json               المواضع: x, y, z(منسوب التسوية), yaw_deg, النموذج, البصمة
  sites_placement.tscn     مشهد Godot يضع كل مجسّم في مكانه
```
   - **Blender:** شغّل `terrain/import_build.py`؛ يستورد التضاريس ثم كل GLB تحت `Site_<id>` (في مجموعة `Sites`) في مركز المنشأة بمنسوبها ودورانها.
   - **Godot:** انسخ المجلد كاملاً إلى `res://world/` ثم افتح `sites_placement.tscn` (غيّر الجذر في `studio/bridge.py:godot_tscn` إن أردت مساراً آخر). المحاور: (x, z, −y)، والدوران حول Y بنفس الإشارة.
   - المنشآت التي لم تُرسم لها مباني تُسجَّل في `sites.json` بـ`"model": null` مع تنبيه في نافذة التقدّم.
   - المجلد يُنشأ في `<home>/exports/`؛ زر «فتح المجلد» في نافذة التقدّم.

## التحديثات المستمرة
1. ضع في `update.json` اسم مستودعك: `"repo": "اسمك/world-studio"`.
2. ارفع الكود إلى GitHub، وغيّر `VERSION` (أو اكتفِ بالوسم) ثم: `git tag v0.2.0 && git push --tags`.
3. سير العمل `.github/workflows/release.yml` (على ويندوز) يبني **المثبّت** و**حزمة التحديث** `world-studio-app-0.2.0.zip` (+ `.sha256`) ويرفعهما إلى Release.
4. التطبيق عند فتحه يفحص آخر Release؛ يظهر شريط «يتوفر إصدار جديد» ← «تحديث الآن» ← يُنزّل ويتحقق من SHA-256 ويفكّ الحزمة في `app/0.2.0/` ثم يبدّل المؤشر ذرّياً ← إعادة تشغيل. الحزمة بضعة ميغابايت لأنها كود فقط.
5. تحديث فاشل أو تالف لا يغيّر شيئاً؛ و«التراجع» في الإعدادات يعود للإصدار السابق. تُحفظ آخر 3 إصدارات.

## البناء على ويندوز
المتطلبات: Python 3.11 (مع tkinter) وNode 20 وInno Setup. ثم من PowerShell في جذر المشروع: `./packaging/windows/build.ps1`
الناتج: `dist\WorldStudio-Setup-<ver>.exe` (تثبيت لكل مستخدم بدون صلاحيات مدير) و`dist\world-studio-app-<ver>.zip`.
**أول تشغيل** يحتاج إنترنت لتنزيل الحزم (bpy كبيرة، بضع مئات الميغابايت) مع نافذة تقدّم؛ بعدها يعمل فوراً.

## التطوير على لينكس/ماك
`./run.sh` (يلزم `python3.11`). متغيرات مفيدة: `STUDIO_HOME` (مجلد البيانات)، `STUDIO_WINDOW=none|auto|native`، `STUDIO_PORT`، `STUDIO_UPDATE_FEED` (رابط JSON بصيغة GitHub لاختبار التحديث).
الاختبارات: `python -m pytest tests` (12 اختباراً: البيئات، المشرف، المحدّث بخلاصة وهمية، واجهة الصدفة).

## إضافة وحدة جديدة
أنشئ `apps/<اسم>/module.json`:
```json
{ "id": "x", "title": {"en": "X", "ar": "س"}, "icon": "★", "env": "app", "needs": [], "cwd": "backend",
  "command": ["{python}", "-m", "uvicorn", "main:app", "--host", "127.0.0.1", "--port", "{port}"],
  "env_vars": {"MY_DATA": "{data}"}, "health": "/api/health", "preferred_port": 8103 }
```
تظهر كتبويب تلقائياً. المتغيرات: `{python}` `{port}` `{data}` `{module}` `{home}` `{code}` و`{env:bpy}`.

## ملاحظات
- تصحيحات في `apps/terrain/blender/import_build.py` اكتُشفت باختبار حقيقي مع bpy 5.0.1 (Python 3.11): f-string بعلامات اقتباس متداخلة (خطأ صياغة على 3.11)، واسم السماء `NISHITA` وخاصية `dust_density` اللذان تغيّرا في Blender 5 (تُجرَّب الأسماء القديمة والجديدة).
- تغيّر `apps/buildings/requirements.txt`: `numpy>=2.1,<3` بدل `==2.5.4` لأن بيئة ويندوز تعمل بـPython 3.11 (مطلوب لـbpy) وnumpy 2.5 يحتاج 3.12+.
- إصلاح في `apps/terrain/frontend/src/App.tsx` (سطرا 286 و289): خطأ TypeScript مع الإصدارات الحديثة (خصائص تُكرَّر في الكائن) بلا تغيير في السلوك.
